TOOLS // THE AGENT'S HANDLES

Thirteen tools

Every tool is a thin relay into the Rust dylib: the plugin registers each tool from the dylib's schema list, and every call dispatches through aphrodite_hermes_dispatch_tool, returning the JSON result verbatim. All handlers share one session store - content compressed by a hook or by aphrodite_compress stays resolvable by aphrodite_retrieve for the life of the session.

13 AGENT-FACING TOOLS + 1 INTERNAL (context_engine_pre_llm)

THERE IS AN INTERNAL 14TH REGISTRY ENTRY, context_engine_pre_llm - THE CONTEXT ENGINE'S OWN PRE-LLM HOOK, NOT A TOOL AN AGENT CALLS DIRECTLY.

CONTRACT // THE MARKER

<<<CCR:hash|type|size>>>

<<<CCR:a1b2c3d4...|build|12,408>>>
[terminal:14L exit code: 0]
  • BLAKE3 hash - pattern ^^[0-9a-fA-F]{8,64}$; truncated hashes never resolve, exact match only.
  • Byte-exact round-trip - aphrodite_retrieve returns the original bytes, nested markers expanded recursively.
  • Workspace-confined reads - path reads are capped at 10 MiB and refuse paths outside the workspace.
  • Markers don't survive a session restart - the dylib is loaded once per process, so a new session starts a fresh store.
SCHEMAS // TWO EXEMPLARS

aphrodite_compress

"content": { string, minLength 1, required }
"type": { enum: code | log | diff | error | json | build_output | text }
"_ccr_center": { string, optional label echoed by aphrodite_catalog }
→ returns { hash, type, size, preview, marker }

Hashes the content, classifies it (or trusts the type hint), keeps it in the session store, and hands back a resolvable marker - park bulky text here instead of carrying it in context.

EXEMPLAR 2 // RETRIEVE

aphrodite_retrieve

"hash": { pattern: ^[0-9a-fA-F]{8,64}$ }
"query": { string, case-insensitive line filter }
"path": { string, direct workspace read, bypassing CCR }
→ { found: true, source: "ccr"|"path", hash|path, content }
→ { found: false, error }

Give hash or path - if both are present, path wins. The query parameter is the cheap way to poke at a large entry without pulling all of it into context.

RULE // META-TOOLS

Meta-tool output is auto-expanded

Output from meta-tools (like aphrodite_stats or aphrodite_catalog) is expanded inline, never compressed - the agent always sees its own engine's status in full. Compressing the catalog would just be the engine hiding its own ledger.
