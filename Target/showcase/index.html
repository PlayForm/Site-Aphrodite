SHOWCASE // THE PLUGIN IN ACTION

The plugin, worked

Every example below is a real behavior of the pipeline dressed in generic content: what the agent sends (the raw stream), what it sees back (the enriched preview), how the bytes come home (the retrieval round-trip), and why the thresholds made that decision. All previews marked as corpus lines are byte-identical to the docs catalog; the rest are faithful fragments. Anonymized throughout - no names, no secrets, no real sessions.

THE DEFAULTS // APHRODITE.TOML

tool_threshold_token = 512 tool_threshold_cache = 4096 terminal_threshold = 1024 inline_threshold = 2048 code_multiplier = 3 engine_threshold_pct = 45 preview_max_chars = 120

These seven numbers decide every example below. Compression is never a judgment call - it is a byte count against the surface's threshold, and the essential tools plus the aphrodite_* tools themselves are always raw regardless of size.

BEHAVIOR LESSON // THE THRESHOLD DECISION

A one-line grep result is far under every threshold: it passes through untouched, no marker, no storage. The same search across a large tree (the grep-search example) crosses the line and becomes a marker. Compression is never a judgment call - it is a byte count against the surface's threshold.

THE CONTEXT ENGINE // WHAT IT DOES NOT DO

Compress returns the transcript unchanged

The registered engine is opt-in (APHRODITE_CONTEXT_ENGINE=1; the TOML key defaults true) and requires Hermes >= 0.20.2 - the first release with pre_tool_call modify. What it does: records token usage from each response. What it never does: should_compress always returns false (it defers to Hermes' own accounting), and compress returns the transcript unchanged - non-destructive, because the transform hooks already shrank the tool output. It never forces a compaction, never rewrites messages, and never touches the inline store.
