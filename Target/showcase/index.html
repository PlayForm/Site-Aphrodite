SHOWCASE // THE PLUGIN IN ACTION

The plugin, worked

Every example below is a real behavior of the pipeline dressed in generic content: what the agent sends (the raw stream), what it sees back (the enriched preview), how the bytes come home (the retrieval round-trip), and why the thresholds made that decision.

All previews marked as corpus lines are byte-identical to the docs catalog; the rest are faithful fragments.

Anonymized throughout - no names, no secrets, no real sessions.

THE DEFAULTS // APHRODITE.TOML

tool_threshold_token = 512 tool_threshold_cache = 4096 terminal_threshold = 1024 inline_threshold = 2048 code_multiplier = 3 engine_threshold_pct = 45 preview_max_chars = 120

These seven numbers decide every example below.

It is the reason compression is never a judgment call: it is a byte count against the surface's threshold, and the essential tools plus the aphrodite_* tools themselves are always raw regardless of size.

THE EXAMPLES // ONE SHAPE EACH

A teal tape marks a corpus-exact preview; a blood-red one marks a faithful fragment.

Every retrieval answers the same way:

→ { found: true, source: "ccr", content: the original bytes, byte-for-byte }

Reads are workspace-confined and capped at 10 MiB; a hash resolves only by exact match - truncated hashes never resolve.

Shell command output with its exit code

Terminal output over the terminal threshold (1024 bytes) compresses to a line that keeps the exit code and line count.

XVIII // CHAIN-SPLIT

Chain splitting a compound command

Opt-in (chain_split=false by default, because invisible segment markers pollute redirected stdout).

With it on, a command with enough segments is rewritten so each segment's output compresses into its own marker - the model sees one build preview and one test preview instead of one blob.

Constructs that would corrupt control flow (heredocs, loops spanning segments) are left untouched.

Fragment; not in the docs catalog.

XIX // THRESHOLDS

What stays raw vs compressed at the defaults

The tier lesson: whether a given output compresses depends on which surface sees it.

The token proxy is aggressive (512), the cache proxy tolerant (4096), terminal output has its own gate (1024), code gets 3x headroom, and the generic fallback preview is the only thing a text blob shows.

Essential tools (read_file, memory, skill_view...) and the aphrodite_* tools themselves are always raw regardless of size.

THE COMMAND

aphrodite_retrieve(hash: "b0c3f6e9a2d5b8e1c4f7a0d3b6e9c2f5a8d1e4b090")

THE OUTPUT

tool_threshold_token = 512 (token proxy: compress above 512 bytes)
tool_threshold_cache = 4096 (cache proxy: compress above 4096 bytes)
terminal_threshold = 1024 (terminal hook: compress above 1024 bytes)
inline_threshold = 2048 (above this, store instead of inline zlib)
code_multiplier = 3.0 (code tier: base threshold x 3)
engine_threshold_pct = 45 (context compression engages at 45% fill)

THE CONTEXT ENGINE // WHAT IT DOES NOT DO

Compress returns the transcript unchanged

The registered engine is opt-in (APHRODITE_CONTEXT_ENGINE=1; the TOML key defaults true) and requires Hermes >= 0.20.2 - the first release with pre_tool_call modify.

What it does: records token usage from each response.

What it never does: should_compress always returns false (it defers to Hermes' own accounting), and compress returns the transcript unchanged - non-destructive, because the transform hooks already shrank the tool output.

It never forces a compaction, never rewrites messages, and never touches the inline store.
