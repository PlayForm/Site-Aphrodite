BENCHMARKS // MEASURED FIGURES

Benchmarks

These figures come from the project's own benchmarks and from a study of the author's real Hermes sessions.

Benchmark ratios are measured; session savings are estimated, and the uncertainty band is shown below.

MEASURED // RATIOS + THE STUDY
THE HEADLINE
MAX COMPRESSION 610× Best case on large low-entropy prose. 132× overall on the same corpus, 106 KB → 800 B. The best case is not part of the per-type chart below - that chart peaks at 416×.
END-TO-END 8-40 ms Including the HTTP round-trip; the headline figure is ~10 ms.
CLASSIFICATION 40-123 ns The compress path itself stays under 1 ms.
MEDIAN 23× Fewer tokens on tool output - the median the README reports for its per-type table.

REAL-WORLD STUDY // MEASURED, SEP 2026
200 HERMES SESSIONS • 6,843 API CALLS • SEP 18-20
TOKENS SAVED 156,342,817 26.9% of the expanded context budget deflected
WITH MARKERS / EXPANDED 424,959,588 / 581,302,405 tokens as stored vs the same payload with every marker expanded (stock Hermes)
SESSIONS SAVED 183 / 200 median session ratio 22.9%; avg 22,921 saved per call
SESSION-SHAPE BAND 20-25% tool-heavy · 76-82% pure-tool the same engine, four payoffs - savings track tool-output volume
RETRIEVAL TAX 2,275 calls / 2,011,583 tokens the re-entry toll, roughly 1.3% of the tokens saved
CHAT-ONLY SESSIONS ~0%
LIGHT DEVELOPER SESSIONS ~5%
TOOL-HEAVY SESSIONS 20-25%
SIMULATED PURE-TOOL LOOP 76-82% a simulated diff+ls+build+search workload - a stress test, not real usage

The study is the author's own work - multi-agent atomization fan-outs, merge/PR work, plugin integration - reconstructed payload-by-payload from the session transcripts.

CAVEAT • THE EXACT PERCENTAGE IS A BAND: ~24-33% ACROSS A 3.0-4.5 CHARS/TOKEN SENSITIVITY RANGE, CENTERED ~27%.
