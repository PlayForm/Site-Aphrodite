Prometheus Metrics

All proxy operations expose counters, gauges, and histograms at GET /metrics in the Prometheus text exposition format, for monitoring, alerting, and dashboards.

This page is the full metric catalog - see Metrics Endpoint for the endpoint behavior and raw output shape, and Metrics Queries for ready-made PromQL.

Endpoint

MethodPathContent-TypeAuth
GET/metricstext/plain; version=0.0.4None

No auth - intentional for local-only deployments (loopback-enforced). Firewall or reverse-proxy auth layer recommended for production.

fill_pct on /health is a different number: compression headroom, not store occupancy.

Retention and Eviction Telemetry

The retention caps and the eviction counter are not Prometheus metrics - they live on /stats/db (SQLite backend only), which is why the catalog above stays at 28 names.

Scrape /stats/db to alert on a store sitting at its cap:

/stats/db fieldMeaning
max_entriesConfigured row cap (store_max_entries), null = unlimited
max_bytesConfigured payload-byte cap (store_max_bytes), null = unlimited
evicted_totalRows evicted by cap enforcement since the store was opened
freelist_bytesPages freed by purge and eviction that the file still holds

A store that sits at max_entries or max_bytes is working as configured, not failing: eviction is a cache policy, so an evicted hash is a retrieval miss exactly like an expired one.

evicted_total climbing steadily while total_entries holds flat is the signal that the cap, not the TTL, is what is reclaiming the store.

Latency Bucket Boundaries

Latency is tracked in 5 fixed buckets, each holding a cumulative count:

Bucket Indexle valueRange
00.001< 1ms
10.011ms - 10ms
20.110ms - 100ms
31.0100ms - 1s
4+Inf>= 1s (unbounded)

Buckets are cumulative in the output, as the format requires: each bucket’s count includes all observations from lower buckets.

The last bucket is labeled +Inf, not 10.0 - it catches every sample at or above 1s (including long outliers), and the explicit +Inf bucket is what makes histogram_quantile() work at all.

/stats JSON Schema

/metrics is built from the same underlying stats as /stats, which returns the full JSON object:

{
    "mode": "token" | "cache",
    "proxy": "aphrodite",
    "ccr_backend": "enabled" | "none",
    "tool_relay_enabled": bool,
    "requests": {
        "total": u64,
        "compressed": u64
    },
    "tokens_saved": u64,
    "ccr": {
        "hits": u64,
        "misses": u64,
        "created": u64
    },
    "tool_relay_calls": u64,
    "cache": {
        "hits": u64,
        "misses": u64
    },
    "latency_buckets_us": [u64; 5],
    "total_latency_micros": u64,
    "compressions_by_type": {"code_rust": u64, ...},
    "compression_ratio_ema": f64,
    "last_errors": ["error string", ...],         // last 5, most recent first
    "request_history": [                          // last 50
        {"id": "uuid8", "method": "POST", "path": "/v1/...", "status": 200, "compressed": true, "elapsed_ms": 1234}
    ],
    "inline_ccr": {"hits": u64, "misses": u64},
    "tool_relay": {"total": u64, "success": u64, "failure": u64},
    "notify": {"success": u64, "failure": u64},
    "upstream_errors": {"4xx": u64, "5xx": u64, "timeouts": u64, "connect_errors": u64, "sse_stream_errors": u64},
    "ccr_store": {"entries": u64, "bytes_approx": u64},  // both live: len() and SUM(LENGTH(original))
    "body_bytes": {"request": u64, "response": u64},
    "upstream_latency_micros": u64
}

compression_ratio_ema is stored at x100 precision in the proxy and divided by 100 for output.

Endpoint: /stats

Loopback only, plus Authorization: Bearer <token> when APHRODITE_MGMT_TOKEN is set (/metrics itself stays exempt so scrapers keep working).

Returns the JSON object above directly.

Also serves /history for the request-history array alone.

Endpoint: /stats/db

Database-level stats, available only for the SQLite (token-mode) backend - the in-memory backend has no database to report:

{
	"total_entries": 3056,
	"total_bytes_original": 45234000,
	"total_bytes_compressed": 73344,
	"oldest_entry_age_seconds": 3421,
	"database_size_bytes": 52428800,
	"freelist_bytes": 81920,
	"max_entries": 100000,
	"max_bytes": 536870912,
	"evicted_total": 0
}

total_bytes_compressed is an estimate (24 bytes per entry, matching the 40-char BLAKE3 hex prefix used as the CCR key); originals are stored uncompressed.

max_entries / max_bytes echo the configured caps and are null when the cap is unlimited (store_max_entries / store_max_bytes = 0).

evicted_total counts rows evicted by cap enforcement since this store was opened, so it resets on restart.

freelist_bytes is the reclaimable slack the file still holds after purge and eviction.

When the backend is in-memory or CCR is disabled, the endpoint still returns HTTP 200 with {"error": "stats_db not available for this backend" | "CCR not enabled", "mode": ...}.
