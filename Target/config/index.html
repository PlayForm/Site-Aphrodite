the pick chain

Where the file is found

Three stops, in order - and a hard fall-through when none of them exists (docs/config/aphrodite-toml.md, "File location"):

1  APHRODITE_CONFIG_PATH  — explicit override. A path that does not exist still counts as set: it falls through to CLI-flag mode, it never silently redirects.
2  ./aphrodite.toml  — the default: the current working directory.
3  ~/.hermes/aphrodite/aphrodite.toml  — the fallback, consulted only when the env var was NOT set; this is where aphrodite setup writes its generated config.
4  none found  — CLI-flag mode: a single proxy, --mode / --listen / --api-key and friends.

the knobs

The compression knobs

The [compression] table is the one section a running proxy re-reads, and only part of it is hot.

Four rows are the hot set: tool_threshold_token, tool_threshold_cache, inline_threshold and code_multiplier.

auto_expand and auto_expand_limit are hot on the same terms, and so are preview_max_chars, the marker format and hint, and ccr_marker_hint.

Everything else in the section is fixed at startup or read once when the dylib loads, which is what the LIVE column above records row by row.

code_multiplier is the only knob that is a multiplier rather than a byte count: the code_* types get the base threshold times its value, so 3.0 hands source three times the default patience and 1.0 hands it none.

inline_threshold decides where compressed content lives: below it the bytes ride inline as zlib, above it they become a durable store entry with a marker.

engine_threshold_pct is the context engine's fill gate, and its two extremes are switches: 0 means never archive and 100 or more means the engine is off.

The two store retention caps are the deliberate exception, because a store cannot resize while it is serving.

store_max_entries and store_max_bytes are read when the SQLite store is opened, so a change to either takes effect on the next proxy restart, not on save.

The dylib keys take a third route entirely: they ride aphrodite_config_set at runtime, so a session can move them without a restart and without a file edit.

per-turn context

[FLOW] / [DIRECTIVES] / [PREVIEWS]

Three sections decide what the model is handed each turn, and none of them touches compression.

[FLOW]

budget_chars = 2600 is the hard cap on ALL per-turn injected context.

The budget covers directives, nudges, the recall catalog and the retrieve hint together, not each one separately.

Sections drop bottom-up when the total goes over; directives and nudges never drop.

Dylib only, overridable through APHRODITE_FLOW_BUDGET_CHARS.

The compiled default is 4,000 characters, so the shipped example buys a leaner turn than a bare binary does.

[DIRECTIVES]

active = ["lazy", "lazy-eval", "foresight"] names which loaded directives start active.

Names that are not in the loaded set are silently filtered out, and an empty list seeds focus, foresight and lazy instead.

The set is runtime-mutable, so a conversation can swap directives mid-flight through aphrodite_directive.

The built-in set is focus, foresight, ccr-handling, cleanup, explore, lazy and lazy-eval - seven files baked into the binary.

[PREVIEWS]

preview_max_chars = 0 caps the whole rendered preview string, not per line, and 0 means unlimited.

model_family = "code_first" selects the [templates.preview.<family>.*] family when [templates] is configured.

The env var APHRODITE_PREVIEW_MAX_CHARS outranks the file, and the file outranks unlimited.

Re-applied by POST /reload.

honest ledger

DOCUMENTED BUT UNWIRED

Five keys parse and do nothing, and the table above marks every one of them UNWIRED rather than quietly omitting them.

catalog_mode lost its reader when the catalog layout became compiled-in, so setting it changes nothing.

classifier_poll describes a poll interval the classifier never had: classification runs per invocation.

prefetch is dead because the aphrodite_prefetch tool is registered unconditionally.

code_structure_map and rust_preview_lines are reserved: they describe a code preview that includes signatures and a line budget for Rust source, and no builder reads either one yet.

The ledger exists because a key that parses and does nothing is worse than an undocumented one: it looks like a lever and behaves like a wall.

env

Every override, live or not

A TOML key is only half the story: the environment wins wherever it is set, and the module documents 68 variables across three surfaces - the Rust proxy, the aphrodite setup subcommand, and the Hermes dylib session.

The last two groups are the ones that matter most: a variable with no reader is a silent no-op, and a build-time variable exported at runtime changes nothing.

WARNING - THE 0.0.0.0 LINES

Listeners bind loopback-only by default, and the router rejects non-loopback peers (and non-loopback Host headers) on every route except /health.

Uncommenting listen = "0.0.0.0:..." exposes an unauthenticated listener to your LAN: /retrieve, /history and /ccr/* have no authentication of their own.

two stacks

One file, two parsers

The READER column above is the whole split - these are the two codepaths that own it.

THE RUST HTTP PROXY

config/proxy.rs, active whenever an aphrodite.toml is found: it reads every row marked PROXY or BOTH, resolving each one as

  • env var
  • then the per-proxy entry
  • then [defaults]
  • then the compiled default.

Three rows are the exceptions, and the ladder marks them: the API key is TOML-first, and the bind address and the mode are per-entry by construction.

THE HERMES DYLIB SESSION

config_loader.rs, read once at dylib load: it reads every row marked DYLIB or BOTH, and the standalone HTTP proxy never reads a dylib-only key.

The FFI runtime-override variant is the aphrodite_config_get / aphrodite_config_set pair on the C-ABI bridge - it surfaces values and changes them mid-session.
