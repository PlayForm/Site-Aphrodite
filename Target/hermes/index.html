HERMES // THE INTEGRATION

Living inside Hermes

Aphrodite connects to Hermes Agent as a native plugin, not as a proxy you point a client at. The plugin registers six hooks, thirteen tools, and an optional context engine, then forwards every call into the Rust dylib. Two proxy processes run alongside as subprocesses, and a canonical runtime home under ~/.hermes/aphrodite/ holds the binaries, config, CCR database, directives, and logs.

COMPARISON // WHY NOT JUST A PROXY
CAPABILITY NATIVE HERMES PLUGIN GENERIC PROXY
Tool output compression transform_tool_result intercepts proxy only sees HTTP traffic
Terminal compression transform_terminal_output no visibility
Context engine opt-in; catalog injected via pre_llm_call unavailable
Auto-launch proxies spawn at plugin load manual aphrodite command
aphrodite_* tools 13 tools in agent namespace agent doesn't know about them
Prompt injection directives, nudges, catalog unavailable
CCR storage token + cache proxy token + cache proxy

THE TRADE-OFF IS REAL AND STATED PLAINLY: THE PLUGIN WORKS WITH HERMES ONLY, WHILE A PROXY WORKS WITH ANY OPENAI-COMPATIBLE CLIENT. THE PROXY PATH STILL EXISTS - POINT base_url AT :9798.

LIFECYCLE // SESSION TO SESSION

What happens when you launch Hermes

hermes starts
→ plugin loads · dylib resolved once per process, smoke-tested in a subprocess
→ a faulting image degrades to "plugin disabled" instead of killing the gateway
→ two proxies spawn - a healthy pair is reused, never duplicated
→ on_session_start resets all per-session state
→ turn loop: pre_tool_call → transforms → pre_llm_call → post_llm_call
→ session ends · markers do not survive a restart - a new session starts a fresh store

THE DUAL PROXIES: TOKEN ON :9798 (SQLITE, PERSISTENT, COMPRESSES ABOVE 1 KB) AND CACHE ON :9797 (IN-MEMORY, COMPRESSES ABOVE 8 KB). NO HOT-RELOAD - RESTART THE SESSION TO PICK UP A NEW BUILD.

OPT-IN // CONTEXT ENGINE

The optional third integration point

Enable with APHRODITE_CONTEXT_ENGINE=1. It is non-destructive by design - the engine's should_compress always returns False, deferring to Hermes' own threshold accounting while the proxy and hooks do the heavy lifting.

engine_threshold_pct 45 # compress at % context fill
engine_protect_first 2 # messages kept at the start
engine_protect_last 5 # messages kept at the end
engine_min_msgs 8 # minimum messages before activating
