PLUGIN // THE THIN LOADER

The plugin

Aphrodite ships as a Hermes Agent plugin: a thin Python registration shim over a Rust dylib. Six hooks, thirteen tools, and an opt-in context engine - all declared in plugin.yaml, all logic living in libaphrodite_hermes.dylib. This page documents the v2.2.6 plugin spec.

v2.2.6 STANDALONE 6 HOOKS 13 TOOLS ZERO LOGIC IN PYTHON
plugin.yaml // THE DECLARED SURFACE

What the manifest declares

name: aphrodite
version: 2.2.6
kind: standalone
requires_hermes: >=0.20.2
requires_hooks: true
provides_context_engine: true
# provides_hooks (6)
on_session_start · pre_tool_call
transform_tool_result · transform_terminal_output
pre_llm_call · post_llm_call
# provides_tools (13)
retrieve · compress · stats · rebuild · files · diff
search · directive · test · catalog
reclassify · prefetch · prefetch_status

ENGINE THRESHOLD SEMANTICS: -1 = ALWAYS COMPRESS · 0 = DISABLED · >0 = FILL PERCENT. SKILLS ARE NOT SHIPPED WITH THE PLUGIN - THEY LIVE DEV-SIDE.

ARCHITECTURE // CALL CHAIN

A thin shim, a Rust brain

Hermes Agent (hooks + tool dispatch)
│
__init__.py - ctypes FFI, registers hooks/tools/engine · no logic
│
libaphrodite_hermes.dylib - Hermes bridge (JSON contract) · 6 hooks · 13 tools · schemas
│
libaphrodite (core engine) - ALL compression logic: hooks · resolve · retrieve · marker · preview · directives
│
CCR store - SQLite :9798 / in-memory :9797 / inline

Registration is driven by the dylib: the shim asks the dylib for its hook names and tool schemas and registers one callback per name. No hot-reload - the dylib is resolved once per process; to pick up a new build, restart the Hermes session.

DOWNLOAD // EXPLICIT STEPS ONLY

register() never downloads

Binaries are never shipped in the repository. Fetching them is an explicit setup step you run yourself - and the verification is mandatory, not best-effort:

  • SHA-256 against the in-tree checksum list - SHA256SUMS.txt, generated by CI into the tree; a mismatch is refused outright.
  • Magic-byte validation - the downloaded file must be a real ELF / Mach-O / PE image, or it is rejected.
  • Backup + restore - an existing install is backed up and restored if any step fails. No release-hosted fallback.
  • A missing binary disables, not breaks - the plugin logs the setup command and stays disabled until the binaries are present.
$ git clone https://github.com/PlayForm/Aphrodite-Hermes.git
$ cd Aphrodite-Hermes
$ ln -s "$(pwd)" ~/.hermes/plugins/aphrodite
$ bash download.sh // or: pwsh ./download.ps1
$ cd ..
$ hermes plugins enable aphrodite
$ hermes
COPY THE FULL SEQUENCE:

LLM API KEY REQUIRED: the proxy is an OpenAI-compatible forwarder and needs its own credentials - APHRODITE_API_KEY, aphrodite setup, or api_key in ~/.hermes/aphrodite/aphrodite.toml. Hermes' provider config is NOT reused, and there is no keyless mode: without a key the proxy refuses to start.

FILESYSTEM // CANONICAL LAYOUT

What changes after install

~/.hermes/
├── plugins/aphrodite ← manual symlink to the plugin repo
└── aphrodite/ ← runtime home
├── binaries/aphrodite ← proxy binary, fetched + verified
├── binaries/libaphrodite_hermes.dylib
├── aphrodite.toml ← config
├── directives/ ← 7 built-ins materialized
├── ccr.db ← SQLite CCR store
└── proxy-stderr.log ← proxy logs (empty = healthy)

The runtime home self-heals toward layout_schema.json at startup: misplaced config and binaries are moved to their canonical paths, stale plugin-source copies are quarantined, and the ~/.hermes/plugins/aphrodite install dir is Hermes-owned - the plugin never creates, converts, or modifies it.
