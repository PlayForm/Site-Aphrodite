PLUGIN // THE THIN LOADER

The plugin

Aphrodite ships as a Hermes Agent plugin: a thin Python registration shim over a Rust dylib.

Six hooks, thirteen tools, and an opt-in context engine - all declared in plugin.yaml, all logic living in libaphrodite_hermes.dylib.

This page documents the v2.3.2 plugin spec.

plugin.yaml // THE DECLARED SURFACE

What the manifest declares

name: aphrodite
version: 2.3.2
kind: standalone
requires_hermes: >=0.20.2
requires_hooks: true
provides_context_engine: true
# provides_hooks (6)
on_session_start · pre_tool_call
transform_tool_result · transform_terminal_output
pre_llm_call · post_llm_call
# provides_tools (13)
retrieve · compress · stats · rebuild · files · diff
search · directive · test · catalog
reclassify · prefetch · prefetch_status

ENGINE THRESHOLD SEMANTICS: -1 = ALWAYS COMPRESS · 0 = DISABLED · >0 = FILL PERCENT.

SKILLS ARE NOT SHIPPED WITH THE PLUGIN - THEY LIVE DEV-SIDE.

ARCHITECTURE // CALL CHAIN

A thin shim, a Rust brain

Hermes Agent (hooks + tool dispatch)
│
__init__.py - ctypes FFI, registers hooks/tools/engine · no logic
│
libaphrodite_hermes.dylib - Hermes bridge (JSON contract) · 6 hooks · 13 tools · schemas
│
libaphrodite (core engine) - ALL compression logic: hooks · resolve · retrieve · marker · preview · directives
│
CCR store - SQLite :9798 / in-memory :9797 / inline

Registration is driven by the dylib: the shim asks the dylib for its hook names and tool schemas and registers one callback per name.

It is the reason there is no hot-reload: the dylib is resolved once per process, so to pick up a new build you restart the Hermes session.

HOOKS // THE CHAIN

Six hooks, one turn

Every hook is a thin dispatch that forwards its arguments to the Rust dylib and hands the JSON reply back to Hermes.

It is the reason the shim registers one callback per name: on plugin load it asks the dylib for its hook names, and the six below are always registered together.

The turn, in order

session starts
→ on_session_start · reset per-session state
↓
user turn
→ pre_tool_call · auto-background, chain split
↓
tool or terminal runs
→ transform_tool_result / transform_terminal_output · compress to marker
↓
→ pre_llm_call · inject directives, nudges, recall catalog
↓
LLM responds
→ post_llm_call · archive turn, advance counter, expire
↓
⟲ next turn

THE SIX // ONE CARD EACH

01 // on_session_start

Resets every piece of per-session state to a clean baseline: turn counter, conversation index, recent markers, referenced files, tool-event telemetry, ephemeral directives.

Injects nothing - the one-shot first-turn orientation renders later, on the first pre_llm_call.

02 // pre_tool_call

Two interventions before a tool executes.

Auto-backgrounding: the hook rewrites long-running terminal/process calls to run in the background (poll worker, default on).

Chain splitting (opt-in): the hook splits chained commands with invisible segment markers so each segment compresses into its own CCR marker.

Otherwise the call passes through unchanged.

03 // transform_tool_result

After every tool call: record telemetry, run the skip gates, classify the content type, hash (BLAKE3), store, and replace the output with <<<CCR:hash|type|size>>> plus a compact preview.

The hook tracks file references before the gates, so aphrodite_files sees every read even when nothing was compressed.

04 // transform_terminal_output

Same pipeline for shell stdout/stderr.

The hook records non-zero exit codes as failures for the error-loop detector; chain-split segments compress unconditionally, before the threshold gate, so marked output never leaks raw; everything else passes the 1,024-char gate first.

05 // pre_llm_call

Runs the poll-worker checkpoint, then the context assembler: first-turn orientation (turn 0 only), [directives:] (never dropped), [nudge:] one-shots at most two (never dropped), background-task status, and the [recall] catalog - the first section dropped under pressure.

One hard budget: 4,000 chars.

06 // post_llm_call

Archives the last marker of the turn into the conversation index (so aphrodite_diff can report per-turn compressions), advances the turn counter, purges expired nudges after the counter advances - a one-shot nudge renders exactly once - and expires stale poll-worker tasks.

BYPASS // THE ESSENTIAL-TOOL GATE

What never gets compressed

A result is left untouched when it is empty, below threshold, or from the essential set - tools the agent needs raw:

skill_view · skills_list · skill_manage · memory · session_search · read_file · read_terminal

Aphrodite also skips its own tools and headroom helpers - compressing aphrodite_retrieve would just replace resolved content with another marker.

THRESHOLDS // GATES AND BYPASSES

The numbers that decide

HOOK SETTING DEFAULT BYPASS
transform_tool_result tool_threshold_token 4,096 empty · essential tools · self tools · 0 = always compress
transform_terminal_output terminal_threshold 1,024 empty · below threshold · 0 = always compress
pre_llm_call flow budget_chars 4,000 recall catalog drops first; directives and nudges never drop
pre_tool_call (chain split) chain_split_min_segments - feature off by default (chain_split = false)

PRECEDENCE: ENVIRONMENT > TOML > DEFAULT (APHRODITE_TOOL_THRESHOLD_TOKEN · APHRODITE_TERMINAL_THRESHOLD · APHRODITE_FLOW_BUDGET_CHARS · APHRODITE_CHAIN_SPLIT).
