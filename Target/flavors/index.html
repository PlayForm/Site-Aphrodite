FLAVORS // THE ROADMAP

One engine, many hosts

A tool call's output becomes part of the model's context, and the engine that rewrites it before the model reads it can live in more than one host.

Aphrodite's compression engine does not belong to one agent.

It is the reason the same CCR core ships in more than one shape: the native Hermes plugin is the flagship flavor today - the deepest integration, the most capabilities - while a standalone listener serves any OpenAI-compatible client, and the engine's core is an embedded fork built to stay portable.

01 // THREE HOSTS // ONE CORE

What ships, and what each one sees

A host can only compress what it can see, so the flavors are ordered by how much of the turn each one is exposed to - and that ordering is what decides which compression the flavor can perform.

WHICH ONE TO RUN

If the agent is Hermes, the plugin is the deepest integration and it ships today. If it is any other OpenAI-compatible client, the standalone proxy already works and simply sees less of the turn.

Embedded Headroom is the core the other flavors carry rather than a host you adopt on its own, and further hosts are planned on the same hook-and-tool pattern.

03 // THE OTHER HOSTS

What each one gives up

Each of these runs the same core behind less of the turn, and each card names the reach it trades away - the host it asks for, what it can see, and what it cannot.

FLAVOR 02 // STANDALONE PROXY

The HTTP body - no hook interception

Point base_url at :9798 (or :9797) and the same compression engine sits between the client and its LLM - token and cache listeners, SQLite or in-memory storage.

What it cannot do is see inside the agent: no hook interception, no tools, no prompt injection.

The portable core

HOST
The engine's own core
WHAT IT SEES
Content types and previews, not agent APIs

Aphrodite embeds Headroom - a custom fork, tracked as a git submodule - as its content-transform core:

  • the classifier
  • the smart crusher
  • the tokenizer.

The Hermes-specific layer is a thin bridge on top.

It is the reason new host flavors are possible: the engine already speaks in content types and previews, not in agent APIs.
