FLAVORS // THE ROADMAP

One engine, many hosts

Aphrodite's compression engine does not belong to one agent. It is the reason the same CCR core ships in more than one shape: the native Hermes plugin is the flagship flavor today - the deepest integration, the most capabilities - while a standalone listener serves any OpenAI-compatible client, and the engine's core is an embedded fork built to stay portable.

The full integration

Six hooks, thirteen tools, the context engine, auto-launched dual proxies - the native flavor sees everything the agent sees.

FLAVOR 02 // STANDALONE PROXY

Any OpenAI-compatible client

Point base_url at :9798 (or :9797) and the same compression engine sits between the client and its LLM - token and cache listeners, SQLite or in-memory storage.

What it cannot do is see inside the agent: no hook interception, no tools, no prompt injection.

FOUNDATION // EMBEDDED HEADROOM

The portable core

Aphrodite embeds Headroom - a custom fork, tracked as a git submodule - as its content-transform core: the classifier, the smart crusher, the tokenizer.

The Hermes-specific layer is a thin bridge on top.

It is the reason new host flavors are possible: the engine already speaks in content types and previews, not in agent APIs.

ROADMAP // PLANNED

Other agents

Beyond Hermes, additional host flavors are planned - the standalone proxy path already works with any OpenAI-compatible agent today, and deeper native integrations follow the same hook-and-tool pattern the Hermes plugin established.

No dates are promised on this page; when a new flavor ships, it is documented here.
