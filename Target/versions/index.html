CURRENT // SHIPPED

The pairing that ships today

BINARY RELEASE
v1.8.1
HERMES PLUGIN
v2.3.2
2026-11-14

Two numbers, one release:

  • the binary carries the proxy, the CCR store and the dylib the shim loads
  • the plugin spec carries the hook names, the tool schemas and the version floor the dylib needs from Hermes.

They are released as a pair on purpose. A plugin that loads a dylib older than its own schemas registers tools that do not exist, so the two versions travel together and the changelog head declares the pairing in its first lines.

CONTRACT // HOW A PAIRING IS CUT

Four files have to agree before a tag exists

A release is not a tag on one repository. The binary, the plugin spec and the pin that connects them are three files that must agree, the in-tree checksum list is the fourth, and the changelog head is where the agreement is written down so a later reader can check it without diffing manifests.

The order matters as much as the numbers. Since v1.4.6 the plugin is tagged before the parent, so the pin resolves to an asset that already exists rather than to a release page that is still uploading.

THE PAIRING // BOTH HALVES
EVIDENCE // A
THE BINARY
v1.8.1, from crates/aphrodite/Cargo.toml: the proxy, the CCR store, and the cdylib the shim loads.
THE CHANGELOG HEAD
Names the version, the date and the one-line title on its first line, and states the pairing the release was cut against - the two manifests are what that sentence is checked against.
THE CHECKSUM
SHA256SUMS.txt ships in the tree and is the only checksum source of truth: a missing file, a version mismatch or a missing asset entry is a hard refusal.

v2.3.2, from plugins/aphrodite/plugin.yaml: hook names, tool schemas, and the requires_hermes floor that decides which Hermes can load it.
THE PIN
BINARY_VERSION reads 1.8.1. The downloader fetches the binary release that file names, never the newest tag on the repository.
THE ORDER
Since v1.4.6 the plugin is tagged first and the binary second, so the pin a reader finds at tag time is already resolvable.

The release's own one-line title, taken from the changelog head rather than paraphrased. It is the shortest honest summary a release can carry: one sentence a reader can hold while working through the register.

CHANGELOG // V1.8.1

What this release changed

The changelog is grouped by what a change is for, not by which file it touched:

  • a fix that closes an advisory
  • a fix that closes a class of drift
  • and the chores that keep the tree honest about itself.

Each group carries its entries verbatim and one line on why the group exists.

FIX // DEPENDENCY SECURITY
- rusqlite 0.40.2 -> 0.41 in the owned headroom fork; bundled SQLite 3.54.1; closes RUSTSEC-2026-0459
- no API reaches the parent: CcrStore, SqliteCcrStore and the retention surface are unchanged
- rustls 0.23.46 / rustls-webpki 0.103.17 / webpki-roots 1.0.12 resolve without constraint changes

WHY // The vendored fork is where SQLite actually lives, so the advisory has to close there and not in the parent crate that never sees it.

FIX // TOOL CATALOG
- aphrodite_debug sits behind #[cfg(debug_assertions)] in schemas.rs, tools.rs and debug.rs
- cargo build --release registers exactly the 13 declared production tools; a debug build registers 14
- hermes plugins validate rule 6 holds for a release dylib without touching the tree

WHY // A staging step that removes a tool by hand is a step that can be forgotten; a cfg gate is enforced by the compiler on every build, in every profile.

CHORE // TRUNCATION
- U+2026 -> ... in the preview builders, the directive builders and loader, and the default marker hint
- apply_preview_cap takes max_chars - 4 and appends ...] so the closing bracket still fits
- the directive cap keeps MAX_DIRECTIVE_CHARS + 3 and MAX_COMBINED_CHARS + 4

WHY // ASCII is one byte where U+2026 is three, and the cap arithmetic has to agree with what it emits or the marker overruns the budget it was sized for.

DOCS // README + TREE
- README gains LLM provider configuration, Verify it's running, See It Work, session lifecycle, directives
- docs/README.md and docs/architecture/README.md stop pinning a binary/plugin version
- retention documented in sqlite, prometheus, lifecycle and aphrodite.toml.example

WHY // A docs tree that pins a version it does not own drifts on the next release; pointing at the manifests makes it self-correcting instead of re-edited.

CHORE // PLUGIN TRACK
- plugin.yaml 2.3.1 -> 2.3.2 with its install_message header and the plugin README badge
- BINARY_VERSION 1.8.1, and the in-tree SHA256SUMS.txt regenerated to match

WHY // Three commits landed past v2.3.1 with no tag, so the plugin version advances to match the binary it ships beside.

TIMELINE TAPE // v0.7.0 -> v1.8.1

The tape, one stamp per release

Each strip is one release stamp: the binary and the plugin version it paired, the one-line "what landed", and the release note.

The tape runs top to bottom in release order - the enlarged perforations mark the two stamps that changed the project's shape (the first crates.io publish, the chain-split CCR).

Every stamp also carries the line the register has no room for: why the release mattered. A version number records that something happened; the reason is what a reader can actually use a year later.

ENLARGED = SHAPE CHANGE THIN = ORDINARY RELEASE 13 STAMPS
STAMP 01 / 13 2026-06-17 PLUGIN: PYTHON ERA (PRE-2.0) THE FIRST ARCHITECTURE
v0.7.0
WHAT LANDED

Atomization + live containers: the Python plugin split into 29 nested modules; terminal output streams instead of blocking.

WHY IT MATTERED

It is the release that gave the project a shape: once the plugin is 29 modules and terminal output streams, every later port has somewhere to land, and a long command stops being a page of silence.

RELEASE NOTE ↗
STAMP 02 / 13 2026-07-13 PLUGIN v2.0.5 FIRST CRATES.IO
v1.2.2
WHAT LANDED

First crates.io publish: aphrodite-headroom-core 0.1.1 -> aphrodite 1.2.2 -> aphrodite-hermes 1.2.2; classification re-measured at 40-123 ns.

WHY IT MATTERED

Publishing is what turned a private tool into an install: the three crates resolve from crates.io in dependency order, and 40-123 ns is the first classification figure the project could point at instead of assert.

RELEASE NOTE ↗
STAMP 03 / 13 2026-07-14 PLUGIN v2.0.x RUST MATURITY
v1.3.2 -> v1.3.4
WHAT LANDED

Rust maturity: the losslessness sweep (hash the ORIGINAL, never the wrapper) and the lossy-arguments fix; then high-intelligibility previews at 132× overall.

WHY IT MATTERED

Hashing the ORIGINAL is the property the marker scheme rests on: hash the wrapper and the same bytes compress into two different markers, so a retrieval returns a copy that never matches the next turn.

RELEASE NOTE ↗
STAMP 04 / 13 2026-09-19 PLUGIN v2.1.4 CHAIN-SPLIT + PLUGIN-FIRST
v1.4.6
WHAT LANDED

Chain-split CCR + the first plugin-first release: the plugin tagged before the parent, so BINARY_VERSION 1.4.6 points at assets that already exist.

WHY IT MATTERED

Two changes in one tag. Chain-split gives each segment of a chained command its own marker, so one 40 KB output becomes several small retrievals; plugin-first ordering means the pin never points at an asset the release has not uploaded yet.

RELEASE NOTE ↗
STAMP 05 / 13 2026-09-20 PLUGIN v2.2.0 EDITION-2024
v1.5.0
WHAT LANDED

Edition-2024 + atomization: the flat src/*.rs promoted into per-item module trees; the aphrodite_debug tool lands.

WHY IT MATTERED

Edition 2024 and per-item module trees are the layout the rest of the port grows into, and aphrodite_debug arrives as the tool that reads a stored entry back when a marker and its content disagree.

RELEASE NOTE ↗
STAMP 06 / 13 2026-09-21 PLUGIN v2.1.5 FORK PUBLISHED
v1.5.1
WHAT LANDED

Headroom fork publication 0.1.3: the fork's accumulated changes finally reach crates.io, replacing the stale July 0.1.2.

WHY IT MATTERED

The fork is where the transforms live, so a stale fork on crates.io is a stale classifier in every install; 0.1.3 is the release that closed the gap between the tree and what the registry served.

RELEASE NOTE ↗
STAMP 07 / 13 2026-09-24 PLUGIN v2.2.0 DIAGNOSTICS
v1.6.0
WHAT LANDED

Config diagnostics + opt-in auto-reload (issue #38): a broken aphrodite.toml can no longer fail silently to defaults.

WHY IT MATTERED

Falling back to defaults in silence is the worst thing a config layer can do - a typo reads as a deliberate setting. Diagnostics make the file answer for itself, and auto-reload stays opt-in because a running session should not change under the operator.

RELEASE NOTE ↗
STAMP 08 / 13 2026-09-25 PLUGIN v2.2.3 ONE HOME
v1.6.3
WHAT LANDED

One runtime home (issue #40): the shim and the Rust half resolve one shared home instead of $HERMES_HOME vs $HOME.

WHY IT MATTERED

Two halves resolving two different homes is a bug that only shows on someone else's machine; one shared home retires the whole class instead of documenting a workaround for it.

RELEASE NOTE ↗
STAMP 09 / 13 2026-10-05 PLUGIN v2.2.5 CHECKSUM LAW
v1.6.5
WHAT LANDED

Checksum law: the in-tree SHA256SUMS.txt is the only checksum source of truth; a missing file, version mismatch, or missing asset entry is a hard refusal.

WHY IT MATTERED

A checksum that can be skipped is not a checksum. Making a missing file, a version mismatch and a missing asset entry each a hard refusal is what lets a download be verified rather than hoped for.

RELEASE NOTE ↗
STAMP 10 / 13 2026-10-07 PLUGIN v2.2.6 CATALOG REVIEW
v1.6.6
WHAT LANDED

Catalog review: aphrodite_prefetch refuses .env, auth.json, ~/.ssh, the Hermes home and non-file paths; setup treats the Hermes plugin dir as report-only; the dylib arm refuses an install without in-tree checksums.

WHY IT MATTERED

This is the release whose review groups appear further down the page: a prefetch that cannot read a secret, a setup that cannot write where it does not own, and a context engine described as opt-in because it is.

RELEASE NOTE ↗
STAMP 11 / 13 2026-10-13 PLUGIN v2.3.0 FEATURE PORT
v1.7.0
WHAT LANDED

Feature port: TOML templates, auto-expand, the context engine, live containers, the Rhai micro-script engine, and recursion/body-size caps - plus a per-session state registry so multi-session gateways stop contending on one global lock.

WHY IT MATTERED

The Python era's behaviour arrives in Rust in one tag, and the shared-gateway lock wedge goes with it: a parent and its subagents no longer serialise on one state lock, and a debug build can log the path it took.

RELEASE NOTE ↗
STAMP 12 / 13 2026-11-08 PLUGIN v2.3.1 BOUNDED STORE
v1.8.0
WHAT LANDED

Bounded CCR store: store_max_entries / store_max_bytes evict the least-recently-accessed rows past either cap, the expiry sweep turns debounced and index-driven (a missing-hash retrieve went 37.40 ms -> 0.22 ms on a 300k-row store), and fill_pct is relabelled as compression headroom; aphrodite-headroom-core 0.2.0 carries the fork-side store limits.

WHY IT MATTERED

Retention is the difference between a store that grows until the disk complains and one an operator can budget: two caps, one eviction rule, and a sweep that no longer runs on every single retrieve.

RELEASE NOTE ↗
STAMP 13 / 13 2026-11-14 PLUGIN v2.3.2 CURRENT PAIRING
v1.8.1
WHAT LANDED

Docs catch up to the engine: the docs tree stops pinning a version it does not own, preview and directive truncation markers go ASCII, and aphrodite_debug is gated at compile time instead of stripped by hand at staging.

WHY IT MATTERED

A release can be small and still change behaviour: the truncation marker now costs one byte instead of three, and the release profile registers exactly the 13 production tools because the compiler says so - not because a staging script remembered to delete one.

RELEASE NOTE ↗
