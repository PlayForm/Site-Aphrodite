HOOKS // THE CHAIN

Six hooks, one turn

Every hook is a thin dispatch that forwards its arguments to the Rust dylib and hands the JSON reply back to Hermes. It is the reason the shim registers one callback per name: on plugin load it asks the dylib for its hook names, and the six below are always registered together.

SEQUENCE // PER TURN
session starts
→ on_session_start · reset per-session state
↓
user turn
→ pre_tool_call · auto-background, chain split
↓
tool or terminal runs
→ transform_tool_result / transform_terminal_output · compress to marker
↓
→ pre_llm_call · inject directives, nudges, recall catalog
↓
LLM responds
→ post_llm_call · archive turn, advance counter, expire
↓
⟲ next turn
THE SIX // ONE SECTION EACH
01 // on_session_start

Resets every piece of per-session state to a clean baseline: turn counter, conversation index, recent markers, referenced files, tool-event telemetry, ephemeral directives.

Injects nothing - the one-shot first-turn orientation renders later, on the first pre_llm_call.

02 // pre_tool_call

Two interventions before a tool executes.

Auto-backgrounding: the hook rewrites long-running terminal/process calls to run in the background (poll worker, default on).

Chain splitting (opt-in): the hook splits chained commands with invisible segment markers so each segment compresses into its own CCR marker.

Otherwise the call passes through unchanged.

03 // transform_tool_result

After every tool call: record telemetry, run the skip gates, classify the content type, hash (BLAKE3), store, and replace the output with <<<CCR:hash|type|size>>> plus a compact preview.

The hook tracks file references before the gates, so aphrodite_files sees every read even when nothing was compressed.

04 // transform_terminal_output

Same pipeline for shell stdout/stderr.

The hook records non-zero exit codes as failures for the error-loop detector; chain-split segments compress unconditionally, before the threshold gate, so marked output never leaks raw; everything else passes the 1,024-char gate first.

05 // pre_llm_call

Runs the poll-worker checkpoint, then the context assembler: first-turn orientation (turn 0 only), [directives:] (never dropped), [nudge:] one-shots at most two (never dropped), background-task status, and the [recall] catalog - the first section dropped under pressure.

One hard budget: 4,000 chars.

06 // post_llm_call

Archives the last marker of the turn into the conversation index (so aphrodite_diff can report per-turn compressions), advances the turn counter, purges expired nudges after the counter advances - a one-shot nudge renders exactly once - and expires stale poll-worker tasks.

BYPASS // THE ESSENTIAL-TOOL GATE

What never gets compressed

A result is left untouched when it is empty, below threshold, or from the essential set - tools the agent needs raw:

skill_view · skills_list · skill_manage · memory · session_search · read_file · read_terminal

Aphrodite also skips its own tools and headroom helpers - compressing aphrodite_retrieve would just replace resolved content with another marker.
