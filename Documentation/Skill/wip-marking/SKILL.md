# WIP MARKING - the site's WIP/unwired laws

## 1. What earns a mark (the truth law)

A doc gets the WIP mark only when a SOURCE states its incompleteness - the
page itself (e.g. docs/centers.md: "v2-v4 are unimplemented design
sketches"), the config docs' "Reserved - no reader" / "Not read by anything"
verdicts, or the CHANGELOG. If the sources do not state a status, FLAG in
the report - never invent a PENDING. A doc that ACCURATELY documents inert
keys (architecture/07-config-resolution.md) is NOT WIP - it describes
reality correctly; the WIP token belongs on the keys, not the page.

Current marked set (verify against sources before changing):

- `centers` - roadmap page: v1 shipped, v2-v4 unimplemented sketches.
- The reserved/unwired config keys carry the `(WIP)` token in the upstream
  docs: docs/config/aphrodite-toml.md ("Reserved - no reader (WIP)" cells,
  the engine_* write-only note, "Not read by anything (WIP)",
  `[templates.*]` reserved/aspirational), docs/config/env-vars.md
  ("Documented but currently unwired (WIP)" heading + its intro reference),
  docs/plugin/context-engine.md (the write-only `engine_*` WIP note).

## 2. The single registry drives every Site mark

`Source/pages/docs/[...slug].astro` owns `const WipDocs = new Set([...])`
of collection ids. It must be declared BEFORE the `Sections` builder (which
consumes it per entry). It feeds three renderings, all in the same file:

- the sidebar entries (`Wip: WipDocs.has(Page.id)` in the Sections map),
- the page header stamp (raw-blood `WIP` chip at `right-0 top-0` of the
  header block, above the 4px crimson rule, `rotate-1`),
- the section-index card badge next to the entry title.

`Source/Component/DocsSidebar.astro` renders the badge: a canary chip
(`bg-stamped-canary text-soot-black`, 13px floor, `font-mono font-black
uppercase tracking-widest`, border black, `title="Roadmap: partly
unimplemented"`) after `{Entry.Title}`; the Entry interface carries
`Wip?: boolean`. Label is `WIP` everywhere (chosen over PENDING: shorter in
the narrow sidebar; the user asked for "PENDING or WIP").

## 3. The generated-content rule (upstream first)

`Source/Content/Docs/**` is GENERATED by `Scripts/Docs/Generate.ts` from
the repository's `docs/` tree (one level up from Site). Content-level
markings (the `(WIP)` tokens) must be edited in `docs/` upstream; editing
the generated copies is wiped on the next build. The Site layer
(registry, sidebar, header) is hand-written and edited directly.

## 4. The verification gate

After any WIP change: `pnpm prepublishOnly` (63 pages), then grep the built
HTML - the centers page header stamp, the sidebar badge on a non-centers
docs page (appears twice: desktop sidebar + mobile drawer), the section
card badge on /docs/, and the `(WIP)` tokens in the built config/plugin
pages - then `pnpm run Drift` (all PASS, count is dynamic). Report the
identification table (item -> anchor -> verdict), the before -> after
anchors, and the arbiter tails.
